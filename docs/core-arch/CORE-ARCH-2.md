## 1. Почему L0 — первый слой, и какой он

**Голосования в репозитории нет.** ФАКТ: поиск по `vote|голосован|root candidate|кандидат.*корн`
не нашёл записи конкурса на базовый слой. Нашлись только правила, по которым голосование не решает
(PROTO-DEC-0041 п.5, `PAIRED-CYCLE.md:153`). Поэтому кандидата я определяю по совпадению всех
источников, которые его называют:

| Источник | Что называет базовым слоем |
|---|---|
| M §4 (Claude) | «0 — схема процедуры и функция перехода (мета-корень)» — первая из корневых процедур |
| M §5 (владелец) | «мета-корень — очень короткая инструкция высшего приоритета… общий принцип построения любой процедуры» |
| M §5 (схема с поправками) | «0 Мета-корень: инварианты, приоритет источников, схема процедуры, правило чтения, "не нашёл правило — стоп"» |
| P, раздел L0 | «Meta-root: invariants, source priority, how procedures are made» |
| E | «Уровень 0 (Мета-корень)»; конфликт с ним — повод для эскалации |
| O (2026-09-24) | «начинаем с самого базового слоя L0… процедура на создание процедуры» |

Шесть из шести совпадают: **L0 = мета-корень, и процедура создания процедур — его ядро**.
**Принято владельцем 2026-09-24 (PROTO-DEC-0055 п.4): голосования вне репозитория не было, этап 1 идёт сейчас.**

## 2. Что входит в L0

Правило разделения (M §4, «[Claude] Возражение»): **процедурные** правила («что дальше») уходят в
ветки; **инварианты** («никогда и нигде») остаются в корне либо исполняются скриптом. Корень —
это мета-процедура плюс инварианты плюс карта.

## 3. Метод владельца: пять классов доказательств

Владелец задал четыре класса. Я добавляю пятый — **E**, вывод из обращения: без него ядро
только растёт (M §3, «ядро только растёт»). Владелец отклонил вывод по неиспользованию
(PROTO-DEC-0060): кандидатов находит P-L0-006, вывод — только после сравнительного теста P-L0-007.

| Класс | Смысл | Что должно быть в досье | Статус после одобрения |
|---|---|---|---|
| **A** | Процедура есть, и её наличие принесло пользу | событие, где она поймала или предотвратила дефект: `путь:строка` или id решения, и цена, которую она сэкономила | `active` |
| **B** | Процедуры не было, и это навредило | инцидент, его цена (попытки, минуты, вмешательства владельца), корневая причина, и почему процедура закрывает **класс**, а не случай; плюс регрессионный «золотой» пример | `active`, для скрипта — после теневого прогона (0047 п.8) |
| **C** | Консенсус считает полезной новую процедуру | источники с отметками согласия (CORE-ARCH-1 §2): не меньше двух независимых ✔ и ни одного ✘ с воспроизведением; ожидаемая польза, метрика, критерий отказа, срок | `trial` → `active` или `retired` |
| **D** | Консенсус считает полезным изменить существующую процедуру | то же, что C, плюс ссылка на старую версию, разница и почему старая хуже | новая версия `trial`, старая `superseded` после испытания |
| **E** | Процедура вредит или устарела | находка P-L0-006 (две копии правила, исчезнувший предмет, цена без пользы) и результат теста P-L0-007; неиспользование — не довод | `deprecated` → `retired`: текст уходит в архив, остаётся указатель |

Правила доказательств:
- Каждая ссылка — `путь:строка`, id решения или id сигнала. Пересказ без ссылки — УТВ., а не доказательство.
- Цена считается в тех единицах, в каких её записывает PROTO-DEC-0051 п.1: попытки, минуты, вмешательства владельца.
- Класс C и D **не** становятся `active` без испытания. Испытание — теневой прогон или пилот с метрикой.
  Так правило «теоретической пользы» не превращается в правило «кто-то так думает».

## 6. Бюджеты, идентификаторы, имена

- Корень ≤ 8 000 B (~2k токенов; M §5). Базовый пакет (корень + CATALOG) ≤ 16 000 B.
  Пакет листа (корень + роль + процедуры этапа + инструменты) ≤ 40 000 B. ГИП.: это втрое меньше,
  чем ~62k токенов, которые реально грузил сертификатор (M §2). Мерить после этапа 6.
- Id: `P-L<n>-<nnn>` — процедура; `S-<nnn>` — сценарий; `ROLE-<slot>`; `TOOL-<name>`; `APP-<name>`;
  `M-<nnn>` — метрика; `R-L<n>-<nn>` — атомарное правило внутри процедуры. Id не переиспользуется
  никогда, даже после `retired`.
- Версия: `version: <major>.<minor>`. Изменение класса D повышает major; уточнение без смены смысла — minor.
- Статусы: `draft` → `review` → `trial` → `active` → `deprecated` → `retired`; и `superseded`.

## 7. P-L0-001 кратко (полный текст — `stage-1/P-L0-001-procedure-lifecycle.md`)

```
 Триггер: сигнал procedure-gap | fall | script-candidate; директива владельца; консенсус исследования; инцидент
   ↓
 1 Приём: id сигнала или триггера, нет ли уже процедуры (CATALOG + grep) ─ есть → путь «изменение» (класс D)
   ↓
 2 Класс A/B/C/D/E + слой (одно место) + кандидаты-дубли
   ↓
 3 Досье: доказательства по классу, цена, таблица рисков (0049 п.4)
   ↓
 4 Черновик по схеме (все обязательные поля; исполнение S/S~/P/—; указатель на скрипт)
   ↓
 5 Размещение: один дом; повторы заменяются указателями; LCC по затронутым слоям
   ↓
 6 Тест на скрипт (4 условия spec §1) ─ да → задача на скрипт по стандарту 0047 п.8; нет → причина в поле
   ↓
 7 Ревью (не автор): вердикт по закрытому словарю; ≤ 2 попытки на корневую причину
   ↓
 8 Владелец: одобрить | изменить | отклонить ─ обязывающее → блок решения; у мелкой правки владелец подтверждает, что она мелкая
   ↓
 9 Испытание (C, D): тень или пилот, метрика, срок; итог пересчитывает не автор ─ провал → переработка или retired
   ↓
10 Публикация: CATALOG, указатели, манифест
   ↓
11 Жизнь: P-L0-006 на каждом планировании пакета → улучшение (D) или вывод через тест P-L0-007 (E)
```

Обратные рёбра: 5→2 (не нашлось одного дома, 1 раз, затем владелец), 7→4 (FAIL, ≤ 2 попытки, затем
владелец), 9→4 (испытание провалено, одна переработка, затем retired), 11→1 (повторный вход по классу E,
1 раз на запись за пакет, затем владелец); любой шаг → P-L0-002 (правило не найдено).

Это краткий пересказ. Дом процедуры — `stage-1/P-L0-001-procedure-lifecycle.md` (R-L0-12); при
расхождении верен файл процедуры.
