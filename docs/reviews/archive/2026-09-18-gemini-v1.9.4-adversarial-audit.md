## Executive Summary

This hostile adversarial audit examined the full v1.9.3–v1.9.4 implementation (PROTO-DEC-0027, optimizations B1–B3, regex/gate polish C1–C2, and downstream consumer synchronization). While the performance optimizations (test suite run time reduced from 404s to ~139s under full 16-worker concurrency, 176/176 tests passing) and core cryptographic hardening are largely robust, the implementation contains **three critical functional defects**:
1. **Completion Gate False Rejection (F-001)**: The machine validator in `validate-protocol.ps1` uses an unbolded regex `^Reviewer:[ \t]*(\S.*)$` which fails on any review formatted according to the canonical template `templates/reviews/REVIEW.md` (`**Reviewer**: <name>`).
2. **Deep Archive Chain Failure on Historical Data (F-002)**: `verify --deep` in `protocol-handoff.cjs` strictly requires `parentEntry` for all entries with `format: 4`, causing `verify --deep` to fail on real repository history where the transitional v1.9.0 format-4 genesis entry was recorded before the `parent-entry` field existed.
3. **Supervisor `--session-pid` Unusable from CLI (F-003)**: `protocol-lock.cjs` enforces `if (sessionPid !== process.pid)`, making `--session-pid` reject any external supervisor or parent process PID passed on the command line.

The overall verdict is **FAIL** pending these three targeted patches.

### F-001 - [HIGH] - Completion gate regex rejects standard template reviewer heading

- **Location**: `validate-protocol.ps1:447`
- **Confidence**: High
- **Reproduction**:
  ```powershell
  # Test the reviewer regex against canonical template format:
  ('**Reviewer**: DeepSeek' -match '(?m)^Reviewer:[ \t]*(\S.*)$')
  # Returns: False
  ```
- **Impact**:
  In `templates/reviews/REVIEW.md` (line 6), the canonical header is:
  ```markdown
  **Reviewer**: <model name>  
  **Verdict**: [PASS | FAIL | BLOCKED | RECOMMENDATION]  
  ```
  In `validate-protocol.ps1`, line 448 parses `$verdict` with optional asterisks:
  `(?mi)^(?:\*\*)?Verdict(?:\*\*)?:?[ \t]*(PASS|FAIL|BLOCKED|RECOMMENDATION)\b`
  However, line 447 parses `$reviewer` strictly without asterisks:
  `$reviewer = [regex]::Match($content, '(?m)^Reviewer:[ \t]*(\S.*)$')`
  Any review that adheres to the review template (`**Reviewer**: <name>`) fails validation when a task is marked `Completed`:
  `FAIL: independent review must name a Reviewer: docs/reviews/...`
- **Recommendation / Proposed Fix**:
  Update line 447 in `validate-protocol.ps1` to match line 448's Markdown-tolerant pattern:
  ```powershell
  $reviewer = [regex]::Match($content, '(?mi)^(?:\*\*)?Reviewer(?:\*\*)?:?[ \t]*(\S.*)$')
  ```

### F-002 - [HIGH] - `verify --deep` fails on real archive due to transitional format 4 root

- **Location**: `protocol-handoff.cjs:253-255`
- **Confidence**: High
- **Reproduction**:
  ```bash
  node .ai/bin/protocol-handoff.cjs verify --owner gemini-381fc7800a864cde --deep
  # Output:
  # AI protocol: .ai\worklog\gemini-381fc7800a864cde.md historical link was broken. archived parent sha256:f5fdb3be6fd325317ad57b91cf2a75e64cdf679711e170e889e1a6dc6ce1f30e has no parent-entry link.
  ```
- **Impact**:
  In `.ai/ARCHIVE.md` (lines 426-435), the entry recorded at commit `cb27c76da5d11d7ed502160f858c370bd72ce453` was assigned `digest format: 4` before the `- parent-entry:` field was introduced (its own Open section states: `Open: Merkle parent-entry hash integration in handoff evidence format`).
  `protocol-handoff.cjs` lines 252-255 state:
  ```javascript
  if (record.format < 4) return { ok: true };
  if (!record.parentEntry) {
    return { ok: false, reason: `archived parent ${current} has no parent-entry link.` };
  }
  ```
  Because this transitional root entry has `format === 4` but no `parentEntry`, `verify --deep` unconditionally reports a broken historical link on legitimate archive history.
- **Recommendation / Proposed Fix**:
  Allow a format-4 entry that lacks `parentEntry` (or has `root`/`legacy`) to terminate the backward chain safely:
  ```javascript
  if (record.format < 4 || !record.parentEntry || record.parentEntry === 'root' || record.parentEntry === 'legacy') {
    return { ok: true };
  }
  ```

### F-003 - [HIGH] - CLI `--session-pid` validation rejects valid external supervisor PIDs

- **Location**: `protocol-lock.cjs:168`
- **Confidence**: High
- **Reproduction**:
  ```bash
  node .ai/bin/protocol-lock.cjs acquire --owner test-session --session-pid 12345
  # Output:
  # AI protocol: Invalid --session-pid value: 12345 (must match this CLI process PID 14668)
  ```
- **Impact**:
  Line 168 of `protocol-lock.cjs` checks:
  ```javascript
  if (sessionPid !== process.pid) {
    throw new Error(`Invalid --session-pid value: ${options[i + 1]} (must match this CLI process PID ${process.pid})`);
  }
  ```
  When an external supervisor process (e.g., a background daemon, IDE extension, or shell script) spawns `node protocol-lock.cjs acquire --session-pid $SUPERVISOR_PID`, the spawned Node.js process has its own distinct `process.pid`.
  As a result, `sessionPid !== process.pid` is ALWAYS true for any external CLI caller. This renders the `--session-pid` parameter completely unusable by any external supervisor, contradicting AGENTS.md §6 and QUICKSTART.md §4.
- **Recommendation / Proposed Fix**:
  Validate that `sessionPid` is a positive integer within valid OS limits and that the process is actually alive on the local system, rather than enforcing equality with the ephemeral CLI child PID:
  ```javascript
  if (!Number.isInteger(sessionPid) || sessionPid <= 0 || sessionPid > 4194304) {
    throw new Error(`Invalid --session-pid value: ${options[i + 1]} (must be a positive integer <= 4194304)`);
  }
  let isAlive = false;
  try { process.kill(sessionPid, 0); isAlive = true; } catch (e) { isAlive = e.code === 'EPERM'; }
  if (!isAlive) {
    throw new Error(`Invalid --session-pid value: ${options[i + 1]} (target process is not alive)`);
  }
  ```

### F-004 - [LOW] - `DATE_HEADING_REGEX` contains redundant alternation branch

- **Location**: `protocol-hooks.cjs:216`, `protocol-handoff.cjs:135`
- **Confidence**: High
- **Impact**:
  In `DATE_HEADING_REGEX`:
  `^## \d{4}-\d{2}-\d{2}(?: \d{2}:\d{2}(?::\d{2})?(?:[ ]?(?:[A-Za-z0-9_]+|[+-]\d{2}(?::?\d{2})?|Z))?)? - .+`
  The branch `|Z` in `(?:[A-Za-z0-9_]+|[+-]\d{2}(?::?\d{2})?|Z)` is dead code because `[A-Za-z0-9_]+` already matches `Z`.
  The regex is confirmed ReDoS-safe because it lacks nested repeating groups.
- **Recommendation**:
  Simplify to `(?:[A-Za-z0-9_]+|[+-]\d{2}(?::?\d{2})?)`.

## Deep Dives

### Focus 1: Validator Fast Stubbing (B1) & False Green Risks
The fast stub validator in `tests/helpers.cjs` replaces `validate-protocol.ps1` with a 3-line PowerShell script when `PROTOCOL_TEST_FAST_CHECKS=1`.
- **Isolation**: Scoped strictly to `test-protocol.ps1` via `try ... finally` block restoring `$env:PROTOCOL_TEST_FAST_CHECKS`. No leaks into parent shells or production scripts.
- **Coverage**: All critical validator tests (`validator.test.cjs`, `validator-syntax.test.cjs`, `installer.test.cjs`, `manifest.test.cjs`, `upgrade.test.cjs`, `codex.test.cjs`) match the exclusion regex and execute the real PowerShell validator.
- **Result**: Significant speedup (suite runtime down from 404s to ~139s under 16-way concurrency) with zero loss of coverage for validator-specific tests.

### Focus 2: 16-Way Test Concurrency (B3) & Windows NTFS Stability
- **Isolation**: Each test runs in an independent temporary directory via `fs.mkdtempSync()`.
- **Resource Contention**: Zero port collisions (all operations are filesystem/CLI).
- **Execution**: 176 top-level tests, 193+ assertions passed with 0 unhandled exceptions or EBUSY/EPERM errors on Windows.

### Focus 3: Micro-Optimizations (B2) & Cryptographic Invariants
- **Lazy `anchor()`**: In `protocol-handoff.cjs`, lazy evaluation ensures `record` computes `after = anchor(root)` exactly once after checks run, avoiding redundant subprocess spawning while guaranteeing evidence reflects the post-check tree state.
- **`__dirty` Flag**: Computed directly from `git status --porcelain=v1 -uall -z --no-renames` during `snapshot()`. Attached as non-enumerable property. Because `snapshot()` creates a new object on every call, no stale caching occurs.
- **Unborn HEAD Handling**: `git rev-parse --verify --quiet HEAD` gracefully handles 0-commit repositories via `catch { head = null }`. Both `renderEvidence` and `hooks.context()` cleanly format empty/unborn states (`no commits`, `(No commits yet.)`).

### Focus 4: Archive Merkle Chain & Completion Gate Validation
- **Duplicate Entry Detection**: `verifyArchivedChain` correctly groups entry hashes and rejects duplicates before chain traversal.
- **Body Re-Hashing**: Verified that `archiveEntryRecords` recalculates SHA-256 over normalized body text, successfully detecting tampered archived records.
- **Completion Gate**: Machine check correctly enforces that tasks marked `Completed` have both an adversarial prompt and an independent review in `docs/reviews/`, but suffers from F-001 (Reviewer Markdown bolding).
