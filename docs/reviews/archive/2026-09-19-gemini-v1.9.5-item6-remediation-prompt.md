## Fix 1 (F-001) - registry immutability and coverage must be case-sensitive

`validate-protocol.ps1` compares committed registry rows with `-ne` (case-insensitive) and uses case-insensitive PowerShell hashtables for coverage, so `| dec-0001 | ACCEPTED |` passes.

- Change the positional row compare to `-cne`.
- Make coverage id membership case-sensitive (for example array membership with `-ccontains`, or a `HashSet[string]` with `StringComparer.Ordinal`); `DEC-0001` and `dec-0001` must be different ids.
- Test (`tests/registry.test.cjs`): a case-mutated row (`DEC-0001` -> `dec-0001`, `accepted` -> `ACCEPTED`) produces the immutability `[WARN]` (and/or unknown-id WARN), exit stays 0; the untouched registry stays clean.

## Fix 2 (F-002) - `gate-check` must parse header fields only in the header region

`protocol-handoff.cjs` `gateCheck` currently matches `Date`, `Mode`, `Verdict`, `Receipt-Owner`, `Receipt` anywhere in the file, so an early body line `Date: 2026-01-01` classifies a modern review as legacy and removes the certifying requirements.

- Define the header region deterministically: the text before the first line equal to `---`; if there is no such line, before the first `## ` heading; if neither exists, the whole file.
- Apply the five field regexes to the header region only.
- A missing or invalid `Date` in the header region keeps failing as today.
- Tests: a review with a proper `Date: 2026-09-25` header and a body `Date: 2026-01-01` after `---` must be treated as **new** (fails on missing `Mode`); a review whose header has no `Date` but whose body has one must fail with `missing or has an invalid Date`; existing fixtures without `---` keep passing.

## Fix 3 (F-003) - supervisor/pid bounds must match the writer

`protocol-session.cjs` `isSessionAlive` accepts `supervisorPid > 0`, while `start` rejects `<= 4`; on Windows `process.kill(4, 0)` returns `EPERM` and PID 4 counts as alive.

- Require integer `> 4` for `supervisorPid`; apply the same bound to the `pid`/`sessionPid` fallback (a value `<= 4` is treated as unusable and falls through / returns `null`).
- Unit test (6-state block in `tests/session.test.cjs`): `supervisorPid: 4` with a dead `pid` yields `false`, not `true`.

## Fix 4 (F-004) - review-path citation must be boundary-aware

`gateCheck` uses `section.includes(reviewRel)`, so a citation of `docs/reviews/x.md.bak` or `docs/reviews/x.md-draft` satisfies a binding for `docs/reviews/x.md`.

- Match the normalized review path followed by a path-boundary character (anything other than `[A-Za-z0-9._/-]`), or the end of the section.
- Keep the existing slash normalization.
- Tests: `.bak` and `-draft` citations fail with `does not mention`; an exact citation passes; citations followed by backtick, quote, space, `)` or end-of-line pass.
