---

## 1. Executive verdict

1. **The universal layer must be MCP-free.** Half of the participating models (web chat panels) have no MCP client, and per-client configuration is the maintenance trap the owner wants to avoid. The layer that benefits *all* assistants is a deterministic filesystem artifact generated by a CLI: a Repomix digest under `.ai/runtime/` (git-ignored, disposable), readable by any agent that can read a file, produced by any agent that can run a command.
2. **Recommended arsenal: 0 mandatory servers, 1 optional, 2 deferred, 6 rejected.** Optional: **Repomix MCP in `--sandbox` mode** (Node.js, MIT, same runtime as the protocol, workspace-confined, no daemon). Deferred to pilots: **Serena** (symbol navigation) and **Qdrant local** (semantic search over `docs/reviews/`). Rejected: CodeGraphContext, Graphiti, Context7, Sourcegraph, GitHub MCP, git MCP, repo-context-mcp.
3. **No auto-injection.** The digest must never be pushed into every SessionStart context. Measured: the full kernel+tests digest is ~18.2k tokens compressed / ~88.1k raw; core scripts alone are 3.9k compressed / 21.8k raw. Injecting 18k into every session would tax narrow edits that need one file. The digest is an **on-demand artifact**.
4. **Raw for audits, compressed only for orientation.** `--compress` is lossy and officially experimental; a compressed digest can hide exactly the implementation detail an adversarial auditor must see. Audits and implementations read full files or a raw digest.
5. **One server at a time, hard budget.** At most one live MCP server per adoption phase; total tool-schema budget <= 1,500 tokens; every server must be removable without changing any protocol semantic; no server output may be cited in Evidence or influence a gate.
6. **Corrected numbers from colleagues.** The "kernel ~18k tokens" equals the **compressed** full digest; raw is **88k**. The "60-75%" compression is context-dependent: measured 56% (bin+validator+AGENTS, 8 files), 82% (core4), 79% (full kernel+tests). The "65-75% net token reduction across models" is an unverified projection, not a measurement.

## 4. The schema-tax arithmetic, with real numbers

Per turn, every registered tool's schema is re-sent. Let `T_schema` be total schema tokens, `N` turns:

- Unpruned 4-server stack (colleagues' estimate ~8,650 tokens/turn): a 10-turn session burns ~86.5k tokens before any work. Against a core4 audit that raw-reads 21.8k, this is a guaranteed net loss.
- **Sandboxed Repomix alone**: 5-7 tools, roughly 600-1,000 tokens/turn; 10 turns = 6-10k. Against a full-kernel audit (88k raw vs 18.2k digest) this wins; against a single-file edit (~4-6k raw) it loses.
- **Break-even rule to enforce in the pilot**: adopt an MCP server only if the measured net session-token delta is positive with `T_schema` <= 1,500 and the task set includes at least three broad (multi-file) tasks.

This is why the ordering is: CLI digest first (zero schema tax, universal), MCP second (only if the pilot shows a net win), graph servers last.

Consequences:

1. **MCP cannot be the universal mechanism.** The protocol's context economy must not depend on it (this is already the plan's C2 rule).
2. **The CLI digest is universal.** Every Colabs participant can consume a file produced in `.ai/runtime/` - the MCP-capable natively, the rest via the protocol's existing injection or transcription.
3. **Per-client configuration is the recurring cost.** Mitigation: exactly one optional server, documented once per client, pinned version, removable by deleting one JSON block; no shared databases, ports, or cross-server dependencies (the recommended set has none of these).

## 6. Integrity and safety rules (non-negotiable)

1. **Advisory only.** Graph/cache/MCP output is never evidence: certifying verdicts cite file paths and the tree digest; no Evidence block may reference digest output, and no gate may read it. (Aligns with A4 and C2.)
2. **Staleness.** The digest is regenerated on demand and carries a header with the source tree digest (`protocol-handoff.cjs state`) and the tool version; any mismatch means discard, not trust. The digest lives under `.ai/runtime/` (already git-ignored and digest-excluded), so it cannot stale anyone's receipt.
3. **No repository dependency.** Do not add `package.json`/npm dependencies or committed binaries. Invoke `npx -y repomix@<pinned>` or an owner-installed CLI; if Repomix is absent, the workflow degrades to normal file reads with no failure.
4. **No network.** Use local packing only; never `--remote`/`pack_remote_repository`; the sandboxed MCP mode disables remote packing, which is why it is the recommended mode.
5. **Secrets.** Keep Secretlint enabled; the digest is runtime-only and git-ignored; journals remain secret-scanned.
6. **Lossy compression warning.** `--compress` hides bodies. Orientation/review tasks only; audits and implementation use raw digests or full files.
7. **No auto-install in hooks.** Hook automation must never `npx` anything; generation is an explicit agent/owner action.

## 7. Pilot design (H1) - one variable at a time

Prerequisite: C1 instrumentation (session timing, changed files, handoff completeness) merged first; otherwise the experiment cannot be measured.

| Condition | Stack | Purpose |
|---|---|---|
| A control | native reads only | baseline |
| B | Repomix CLI digest, on demand (raw; compressed for orientation) | tests the universal layer alone |
| C | B + Repomix MCP sandboxed (MCP-native clients only) | tests schema tax vs on-demand packing |
| D | C + Serena, restricted modes (only if B/C show symbol-navigation pain) | tests the expensive option |
| E | deterministic review index over `docs/reviews/` (our own generator) vs Qdrant local | tests the prose-retrieval problem |

Tasks: the 10 colleague-proposed queries are representative; add at least three broad audits and three narrow edits. Metrics: total session tokens (primary), schema tokens, files read, time-to-first-edit, handoff completeness. Acceptance for adoption (pre-registered, before running): >= 25% median total-token reduction on broad tasks with no accuracy regression, no increase on narrow tasks, and `T_schema` <= 1,500. The 35%/50%/65% forecast stays an unverified hypothesis.

## 9. Colleague-report reconciliation

- **Mistral (older, `a6a6d61`)**: recommends running 4 servers with "multiplicative 65-75%" savings. The synergy table is not evidence; running the stack simultaneously is exactly the schema-tax trap. Its per-tool descriptions are otherwise reasonable, and its overlap analysis (Repomix > repo-context-mcp; Qdrant > Graphiti; exclude Sourcegraph/Context7/GitHub/git) matches this analysis.
- **Gemini (newer, `a6dbf8c`)**: correctly identifies the schema tax and cache-staleness danger and proposes the two-tier digest+graph design. Two corrections: CGC on Windows cannot use embedded FalkorDB Lite (Unix-only) and cannot parse PowerShell (not in its 23 languages), and the "kernel ~18k tokens" is the compressed full digest while raw is 88k. Its proposed auto-generation inside `record` should not inject the digest into context, only write the artifact.
- **Transcribed analyses (schema tax, 2-tier)**: the tax math is right for the unpruned stack; with sandboxed Repomix alone the budget is ~600-1,000 tokens/turn. The "MCP Cache > File I/O" priority rule is rejected as written: caches are advisory, files and digests remain authoritative.
