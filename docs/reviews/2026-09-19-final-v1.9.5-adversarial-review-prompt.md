## 3. Facts to verify or refute (commands required)

1. **C0 liveness**: in a throwaway clone, `prune` preserves an empty journal and `cleanup-runtime --force` preserves the snapshot when the registered supervisor PID is alive and the transient PID is dead; both remove them when the supervisor is dead. A recency-only implementation must not pass (age artifacts beyond 15 minutes).
2. **Three-way polarity**: foreign-host state is preserved by `prune` without `--force` and by cleanup even with `--force`; a corrupt state file with an aged journal is quarantined; `--force` never destroys a live supervisor's artifacts; content-bearing journals are never quarantined.
3. **A2 record fix**: a journal at ~140 lines stays <= 150 after `record`, auto-archiving older entries; a single oversized entry fails with `journal entry is too long` and leaves the journal byte-identical; re-record does not grow the journal.
4. **A3 gate-check**: fails on stale receipt, `Mode: ADVISORY`, transcribed reviews, wrong owner, missing/malformed `Date`, missing `Mode` on a new review, absent journal; passes on a valid CERTIFYING review whose owner entry names the review path and whose deep receipt is fresh; legacy (`Date: 2026-09-19`) warns but passes; empty `Receipt` is accepted; `Status: In progress` is not applicable.
5. **Bootstrap**: on a Completed task with no prior evidence, `record --owner <cited>` succeeds (the internal validator skips only gate-check via `PROTOCOL_SKIP_GATE=1`), then `verify --deep` and a standalone `gate-check` pass; mutating a tracked file afterwards fails both.
6. **B registry**: in a clone with the registry committed, removing a row, adding an unknown id, omitting `Reopen-trigger` on a new decision block, or deleting the registry each produce a `[WARN]` with exit 0; a complete registry passes silently; committed rows are immutable against `HEAD`.
7. **Digest/freeze**: writing a review under `docs/reviews/**` stales a prior receipt; writing a journal, rehashing, staging and committing do not change the digest; any new untracked non-ignored file anywhere stales receipts.
8. **Encoding/size**: validator exit 0 with 0 warnings; journals <= 30 and <= 150 lines; `.ps1` ASCII-only; full suite `236/236`.

## 4. Attack vectors

- Break the liveness rule: stale-but-alive supervisor PID, recycled PID, touched empty artifacts, missing/corrupt state, foreign host, lock holder, `--dry-run`.
- Game gate-check: bold/markdown header variants, duplicate fields, `CONDITIONAL PASS`, a review that quotes another review path, an owner entry that mentions the path in body text without being the author, multiple entries and archived parents, `Transcribed by:` phrasing variants, dates in body text vs header.
- Break the registry checks: middle-row insertion, duplicate rows, reordering, case variants of ids/statuses, trigger value with whitespace/case, a new block inside an existing block's body.
- Digest bypass: files under ignored paths that still affect semantics, `.gitignore` edits, worktree tricks, CRLF/no-BOM boundaries, evidence for a section other than the newest.
- Bootstrap and races: concurrent sessions writing journals while a record runs, auto-archive during record, quarantine/restore cycles, the quarantine window, `revert`/`checkout` scenarios.
- CI/workflow: does the restored workflow actually execute every step (compare against `git show 8beca2b:.github/workflows/protocol.yml` plus the escalation wrapper), and does a forced `[WARN]` fail the job?

Report at least one **negative test** (command and output) per mechanism you attack.
