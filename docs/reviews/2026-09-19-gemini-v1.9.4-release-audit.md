### Vector 2: Lock Token & Session Spoofing (PASS)

1. **System PID Rejection**: `protocol-lock.cjs acquire --owner test-spoof --session-pid 4` is immediately rejected with `Invalid --session-pid value: 4 (must be a positive integer > 4 (reserved system PID) and <= 2147483647)`.
2. **Unregistered Foreign PID Rejection**: Supplying an unrelated active OS process ID (e.g. PID 9972) without a matching token fails closed: `--session-pid 9972 is not bound to this session (must be process.pid, process.ppid, or registered PID with valid --session-token)`.
3. **Supervisor Authentication**: Registration tests in `tests/lock.test.cjs` (subtests 10–18) verify that registered supervisor processes presenting the matching 64-character SHA-256 session token are granted ownership, while mismatched tokens fail.
4. **Lock Clear Protection**: Plain `clear-lock` refuses to evict an active registered session; clearing requires `--force` and `--reason`, logging an explicit `[AUDIT WARN]`.
5. **Lifecycle Persistence**: The 32-byte cryptographic nonce is persisted in `.ai/runtime/<owner>.json` across session CLI stops, preventing token invalidation between transient steps.
