## Executive Summary

The implementation passes the focused regression tests, but the release is not
certifiable. Deep archive verification can accept a valid duplicate before a
tampered duplicate, archive append and journal replacement are not one
transaction, cleanup still deletes snapshots with unknown liveness, and the
mandatory adversarial-review rule is not enforced at completion time. These are
integrity and governance failures, not cosmetic recommendations.

### F-001 - MEDIUM - Deep verification stops at first matching archive entry

- **Location**: `.ai/bin/protocol-handoff.cjs:226-243`
- **Confidence**: High
- **Reproduction**: Put a valid archived section containing the requested
  `entry:` hash before a second section with the same hash and a modified body.
  `verify --deep` accepts the first section and exits without inspecting the
  second.
- **Impact**: The fail-closed claim is false when archive content is duplicated
  or appended by an attacker.
- **Recommendation**: Reject duplicate provenance, or parse and verify every
  section referencing the target hash and fail if any body differs.

### F-002 - MEDIUM - Archive and journal update are not transactional

- **Location**: `.ai/bin/protocol-archive.cjs:148-171`
- **Confidence**: High
- **Reproduction**: Let `appendFileSync` succeed, then force all
  `atomicRename` retries to fail. The archive contains the entries while the
  source journal remains unchanged; a later retry appends them again.
- **Impact**: Duplicate history and broken parent/entry continuity can result
  from a crash or Windows sharing violation.
- **Recommendation**: Stage both outputs and use a recoverable transaction or
  make archive append idempotent by entry hash before committing the journal.

### F-003 - MEDIUM - Unknown snapshot liveness is still deletable

- **Location**: `.ai/bin/protocol-session.cjs:226-257`
- **Confidence**: High
- **Reproduction**: Use a snapshot with a foreign hostname or malformed/missing
  PID. The orphan branch can delete it immediately, and the seven-day stale
  branch deletes it without requiring `isProcessAlive(state) === false`.
- **Impact**: A remote or shared-host session can lose its snapshot despite the
  liveness-first requirement.
- **Recommendation**: Every deletion branch must require conclusive `false`;
  preserve or quarantine `null` liveness for manual inspection.

### F-004 - MEDIUM - Completion gate does not enforce adversarial review

- **Location**: `validate-protocol.ps1:388-398`
- **Confidence**: High
- **Impact**: The rule in AGENTS.md, QUICKSTART.md, and PROTO-DEC-0027 is
  descriptive only. A task can be marked `Completed` without a unified audit
  prompt, independent review, or owner sign-off.
- **Recommendation**: Require a linked review artifact with the mandated
  header and verdict, or validate an explicit owner sign-off before completion.

### F-005 - LOW - Heading regex is not shared by all consumers

- **Location**: `.ai/bin/protocol-hooks.cjs:245`;
  `.ai/bin/protocol.cjs:207,209,236`
- **Confidence**: High
- **Impact**: Handoff can accept a timestamped or offset heading while Stop,
  doctor, or telemetry treats the same entry as incomplete or invisible.
- **Recommendation**: Move the parser/regex to a shared module and add
  integration tests for numeric offsets and `UTC`/`Z`.

### F-006 - LOW - CLI stop archive path has a dead `path` reference

- **Location**: `.ai/bin/protocol-session.cjs:112-114`
- **Confidence**: High
- **Impact**: `path.basename` is not in module scope. The resulting
  `ReferenceError` is swallowed by an empty catch, making the CLI archive path
  silently ineffective.
- **Recommendation**: Import `node:path` at module scope and test `stop`
  directly with an oversized journal; do not swallow this failure.

### F-007 - LOW - `--session-pid` is not validated or wired end-to-end

- **Location**: `.ai/bin/protocol-lock.cjs:139,164`
- **Confidence**: High
- **Impact**: The flag is parsed but no shipped session/handoff caller supplies
  it. Non-numeric input can become `NaN` and fall back to the short-lived
  process PID, weakening the intended liveness signal.
- **Recommendation**: Require a positive integer, preserve explicit unknown
  state, and propagate the session PID through all archive/lock callers.

## Per-item Verdicts

1. Mandatory adversarial prompt: **FAIL** — documented but not enforced.
2. Cooperative lock preservation: **RECOMMENDATION** — preservation works,
   but the session-PID interface is incomplete.
3. Atomic rename retry: **FAIL** — retry is local; archive/journal commit is
   not atomic.
4. Legacy evidence compatibility: **PASS** — format `< 4` is classified as
   legacy while modern tampering remains detectable.
5. Deep archive verification: **FAIL** — duplicate entries bypass complete
   verification.
6. Date heading regex: **FAIL** — consumers still disagree.
7. Liveness-first cleanup: **FAIL** — `null` liveness reaches deletion paths.
8. Test and validator coverage: **FAIL** — tests miss the above failures and
   validation does not enforce completion review.

## Recommendations & Actionable Plan

1. Make archive verification reject duplicate target entries and design a
   recoverable archive/journal transaction.
2. Require `isProcessAlive(state) === false` for every snapshot deletion path.
3. Enforce the review artifact/prompt gate in the validator and wire the shared
   heading parser and session PID through all consumers.
4. Add regression tests for duplicate archive entries, rename failure after
   append, foreign-host stale snapshots, CLI stop, and completion without review.
