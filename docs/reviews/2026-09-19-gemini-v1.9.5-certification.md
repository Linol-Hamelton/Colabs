### F-001 - [MEDIUM] - Registry HEAD comparison uses case-insensitive `-ne`

- **Location**: `validate-protocol.ps1:440`
- **Confidence**: High
- **Reproduction**:
  ```javascript
  // In throwaway clone with committed REGISTRY.md:
  const fs = require('fs');
  const regPath = 'docs/decisions/REGISTRY.md';
  const orig = fs.readFileSync(regPath, 'utf8');
  // Mutate DEC-0001 to dec-0001:
  fs.writeFileSync(regPath, orig.replace('| DEC-0001 |', '| dec-0001 |'));
  // Run validator:
  const out = require('child_process').execSync('powershell -ExecutionPolicy Bypass -File .\\validate-protocol.ps1', { encoding: 'utf8' });
  console.log(out.includes('[WARN]')); // Outputs: false (Silent PASS!)
  ```
- **Impact**: In PowerShell, standard `-ne` is case-insensitive (`'dec-0001' -ne 'DEC-0001'` evaluates to `False`). If an author or tool alters the casing of decision identifiers or status strings in `docs/decisions/REGISTRY.md`, the immutability check does not flag the change against HEAD.
- **Recommendation**:
  ```powershell
  # Replace line 440 in validate-protocol.ps1:
  if ($idx -ge $currLines.Count -or $currLines[$idx] -cne $hLine) {
  ```

### F-002 - [LOW] - `gate-check` Date regex matches lines anywhere in body

- **Location**: `.ai/bin/protocol-handoff.cjs:978`
- **Confidence**: High
- **Reproduction**:
  ```javascript
  // Review with NO header Date, but a line in prose starting with 'Date: 2026-01-01':
  const review = '# Review\n\nIntroductory discussion\nDate: 2026-01-01\nVerdict: PASS\n';
  // gateCheck executes and outputs:
  // [WARN] legacy review ... missing Mode: CERTIFYING
  // [WARN] legacy review ... missing Receipt-Owner
  // Exits with code 0!
  ```
- **Impact**: The regex `/^[ \t]*(?:\*\*)?\bDate\b(?:\*\*)?\s*:\s*([^\r\n]+)/im` searches multi-line across the entire document. If a review omits a header Date field but contains a historical date starting a body line, `gate-check` misinterprets it as a legacy review (`Date <= 2026-09-19`), which suppresses the requirement for `Mode: CERTIFYING` and `Receipt-Owner`.
- **Recommendation**: Restrict metadata extraction in `gateCheck` to the header section preceding the first horizontal divider (`---`).

### F-003 - [LOW] - `isSessionAlive` accepts reserved Windows System PID <= 4

- **Location**: `.ai/bin/protocol-session.cjs:42`
- **Confidence**: Medium
- **Reproduction**:
  ```javascript
  // Windows PID 4 (System) throws EPERM on process.kill(4, 0), which checkProcessAlive catches as true:
  const record = { supervisorPid: 4, hostname: require('os').hostname() };
  console.log(isSessionAlive(record)); // true
  ```
- **Impact**: CLI `start` enforces `supPid > 4`, but state reader `isSessionAlive` only checks `record.supervisorPid > 0`. A crafted or corrupted state file containing `supervisorPid: 4` causes `prune` and `cleanup-runtime` to treat the session as alive indefinitely on Windows.
- **Recommendation**: Align `isSessionAlive` with CLI validation: `record.supervisorPid > 4`.

## Deep Dives into Verification Groups

### 1. C0 Liveness and Supervisor Priority
- **Probes executed**: Tested aged empty journals (mtime = -20m) against live supervisor PID (`process.pid`) and dead transient PID (`99999999`).

  - Dead supervisor PID: `prune` reported `quarantined gemini-liveprobe.md` (moved to `.ai/runtime/pruned/`); `cleanup-runtime --force` purged snapshot.
- **Recency invariant**: Tested touched empty journal (`mtime = now`) with dead PID: `prune` without `--force` preserved by recency window (15m); `prune --force` overrode recency and quarantined.

### 2. Three-Way Polarity & Quarantine
- **Foreign-host state**: Aged empty journal with `hostname: "OTHER-REMOTE-HOST"` was preserved by `prune` without `--force` and by `cleanup-runtime` even with `--force`.

- **Content-bearing journals**: Journals containing dated entries are never quarantined under any combination of flags (`prune --force` preserved content journal).
