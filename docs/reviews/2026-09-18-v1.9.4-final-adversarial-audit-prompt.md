## 2. Reviewer Mandate & Attack Vectors

Reviewers are instructed to act adversarially. Hunt for defects, regressions, edge cases, and protocol violations across the following attack vectors:

### Attack Vector 1: Lock Token & Session Spoofing
- Can an external unprivileged process forge a session token or bypass token verification?
- Does PID recycling on Windows create any window where a dead session's lock can be squatted?
- Are child processes spawned by an assistant able to inherit access without exposing raw tokens in CLI arguments or logs?

### Attack Vector 2: Archive Boundary & Merkle Chain Integrity
- Does `canonicalEntryBody` correctly handle all combinations of whitespace, horizontal rules, and batch provenance headers?
- Can an adversary splice a forged entry into `.ai/ARCHIVE.md` without causing `verify --deep` to fail?
- Does orphan detection handle multiple disconnected subgraphs correctly?

### Attack Vector 3: Consumer Synchronization & Version Drift
- Verify that `setup-ai-protocol.ps1 -Target <path> -Force` correctly backs up previous versions and delivers exact SHA-256 byte matches for all 18 managed files.
- Confirm that `setup-ai-protocol.ps1 -Target <path> -Verify` fails if any managed file is tampered with or contains an older version.
- Confirm that repository isolation is maintained: no Git commits were made in consumer checkouts.

### Attack Vector 4: Completion Gate Strictness
- Verify that `validate-protocol.ps1` blocks any task marked `Status: Completed` if:
  - The completion gate section is missing or malformed.
  - The cited prompt or review file does not exist or is 0 bytes.
  - The review verdict is `FAIL` or `BLOCKED`.
  - Any review artifact cited in `TASK.md` does not exist or is empty.
