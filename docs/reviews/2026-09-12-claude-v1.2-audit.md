### Конкретные нарушения и несогласованности

1. **Журнал не совпадает с контрактом hook.**
   `AGENTS.md:88` и `CLAUDE.md:10` требуют использовать имя, выданное SessionStart.
   `protocol-hooks.cjs:89` формирует только `claude-<16 hex>.md`.
   Записаны `claude-20260911-followup.md` и `claude-20260911-publish.md`.
   Без отдельного сопоставления эти записи не могут удовлетворить Stop-хук своей
   сессии. Содержимое существует; исключение или отсутствие hook-запуска не объяснено.

2. **Запись в архив без lock прямо признана Claude.**
   См. [journal:63](https://github.com/Linol-Hamelton/Colabs/blob/0b3b094/.ai/worklog/claude-20260911-followup.md#L63).
   Это нарушение процедуры, а не обнаруженная потеря данных. Шаблоны сами по себе
   не входят в перечень shared documents; доказанное нарушение относится к ARCHIVE.

3. **Отметка полного завершения шире фактического состояния.**
   TASK отмечает согласованность документов и невозможность зелёной проверки при
   неработающем установщике; ниже приведены контрпримеры. PLAN остался In progress.
   DEC-0009:341 и PLAN:28 предусматривают CI; `.github/workflows/` отсутствует.
   Claude честно заметил этот унаследованный долг в журнале публикации, но не закрыл его.

4. **Архивирование закрытых сессий не определено непротиворечиво.**
   ARCHIVE:22 предлагает вырезать старые записи и оставить новые. При 31 файле
   число файлов останется 31. Кроме того, запрет править журнал другой сессии
   не даёт следующему участнику архивировать журнал завершившейся сессии.
   Нужен разрешённый перенос закрытого журнала целиком с проверкой сохранности.

5. **Восстановление lock описано неточно.**
   `docs/PROTOCOL.md:65` называет поле `staleFor`, которого нет; фактические поля:
   `lock.heldForMinutes`, `lock.stale`, `staleAfterMinutes`.
   `AGENTS.md:125` приравнивает возраст lock к аварийному завершению. Сам код
   правильно предупреждает, что медленный живой владелец выглядит аналогично.
   Возраст должен означать необходимость проверки, а не разрешение освобождать lock.

6. **Шаблон решений отстаёт от правила замещения.**
   Шаблоны всё ещё предлагают статус Superseded by, но не поле Supersedes.
   Правило требует нового блока с Supersedes, сохраняя старый блок неизменным.
   Сам валидатор пока не проверяет существование цели или циклы замещений.

### Исправление атрибуции незавершённой работы Codex

Запись `.ai/worklog/codex.md` описывает отдельный обзор репозитория. Фраза
«No implementation ... was changed» верна для того обзора; последующая задача
по реализации не делает историческую запись ложной. Аналогично более поздний
commit не опровергает запись Claude о том, что на момент прежнего отчёта commit ещё не было.

Реальный долг Codex — отсутствующий журнал последующего прерванного hardening:
PLAN и DEC-0009 появились, реализация осталась промежуточной, lock не был освобождён,
operator guide и CI не были закончены. Claude обоснованно обнаружил этот разрыв
и довёл значительную часть работы до проверяемого состояния.

В текущем аудите добавлена ретроспективная запись в новый журнал Codex.
Старые журналы не переписывались. Результаты проверок того прерванного этапа
ретроспективно не приписываются: проверяемые результаты выше получены сейчас.

Git содержит общий commit 79b3f28 без отдельных checkpoints v1.0/v1.1, поэтому
он не позволяет независимо атрибутировать каждую строку Claude или Codex.
Не обнаружено удаления содержательной истории: DISCUSSION и WORKLOG в ae5e831
содержали пустые шаблоны, WORKLOG_HISTORY сообщал об отсутствии архивированных записей.
Baseline сохранён. Сохранность каждого байта решений до общего commit нельзя
доказать по одному Git-снимку; признаков подделки одобрений аудит не установил.

## Что произошло с «чатом обсуждений»

[DEC-0007](https://github.com/Linol-Hamelton/Colabs/blob/0b3b094/.ai/DECISIONS.md#L225)
отменяет отдельный `.ai/DISCUSSION.md`: открытые разногласия попадают в TASK,
одобренные итоги — в DECISIONS. Поэтому отсутствие DISCUSSION не является
нарушением Claude. Полный текст разговоров в репозитории сейчас не сохраняется.

При этом отсутствует структурированная цепочка «замечание -> ответ второго
агента -> результат проверки -> решение владельца». TASK содержит сводные вопросы,
а не полный протокол их разрешения. Этот аудит и ответы на него следует связывать
устойчивыми идентификаторами замечаний. Новое хранилище обсуждений потребовало бы
отдельного решения, меняющего DEC-0007; в этом аудите оно не создаётся.

## Следующие волны: предложения, а не утверждённый план внедрения

### Волна 1 — достоверные проверки и закрытие текущего этапа

- Исправить T1-T5 и T9, добавить тест на каждый контрпример.
- Валидировать все слияния установщика до первой записи; ошибочная конфигурация
  должна оставлять все существующие байты без изменений.
- Включить CI для PR/push: Windows PowerShell 5.1 и PowerShell 7, Node 22,
  validator, полный suite, проверка установочного пакета и diff/encoding.
- Согласовать TASK/PLAN/шаблоны, поля lock и идентификаторы журналов.
- Проверять фактические Git ignore-правила и состояние включения интеграций.
- Зафиксировать единый идентификатор версии: AGENTS называет v1.2, installer v1.1;
  Git tags и release notes пока отсутствуют.

Готовность: каждый известный контрпример имеет регрессию; ошибочное обновление
не меняет проект; CI на точном candidate commit зелёный; документальные статусы
не противоречат артефактам. Настройки обязательных checks/защиты ветки проверить
отдельно: этот аудит не проверял административные настройки GitHub.

### Волна 2 — единый жизненный цикл сессии и межагентная совместимость

- Общий небольшой CLI: start/status/handoff/doctor/archive; единый session ID
  связывает journal, snapshot, lock и проверенные команды.
- Handoff проверяет добавление новой записи и сохранение предыдущей истории,
  а не только различие хэша последней найденной записи.
- Архивирование закрытых журналов целиком под lock, с проверкой хэшей и
  восстановлением после сбоя; начать с dry-run и теста на 31 журнале.
- Формализовать owner и восстановление аварийной сессии, не приравнивать timeout
  к доказанной смерти владельца. Новые операции покрыть тестами с прерыванием.
- Адаптеры Claude и Codex используют одно ядро, но отдельно проверенные события.
  Актуальные [OpenAI Docs](https://learn.chatgpt.com/docs/hooks) описывают
  `.codex/hooks.json`, SessionStart, Stop, Interrupt и SessionEnd. Это делает
  симметричную интеграцию практическим направлением, а не ограничением платформы.
  Репозиторий пока такого адаптера не содержит; доверие проектной конфигурации
  и работа на установленной версии требуют отдельного интеграционного теста.
- Даты/метаданные записи определяют «недавний контекст»; mtime после clone не
  используется как единственное основание. DEC-ссылки получают проверяемый формат.

Готовность: два параллельных запуска не разделяют журнал; 31 закрытый журнал
архивируется без потери текста; restart/interrupt/clone/worktree сохраняют
понятный контекст; обе интеграции проверены в реальных клиентах.

### Волна 3 — доказать пользу на тестовом продукте

Начать после исправления критичных ложных успехов первой волны, не дожидаясь
совершенства всех удобств. Провести 10-20 сопоставимых задач с передачами
Claude -> Codex и Codex -> Claude, включая исправление дефекта, смену решения,
конкурирующие изменения и продолжение после прерывания.

Измерять потерянные ограничения, повторно выполненную работу, уточнения владельцу,
время входа следующего агента в задачу и долю времени на документацию.
Сравнить с простым TASK + один handoff. Предварительные целевые метрики согласовать
до пилота; не выбирать их задним числом по красивому результату. Возможный
ориентир: ноль потерь истории в сценариях отказа, ни одного решения без ссылки
на основание согласования, снижение времени входа без роста общей трудоёмкости.

Готовность: опубликована таблица задач и результатов с неудачами и ограничениями;
видно, какие части протокола дают пользу и какие можно упростить.

### Волна 4 — качество публичного инструмента

- Владелец выбирает LICENSE; добавляются CONTRIBUTING, процесс сообщений об
  ошибках/уязвимостях, release notes, теги и поддерживаемая матрица окружений.
- Проверяемый manifest установочного пакета и миграций; тесты upgrade между
  выпущенными версиями, восстановление из backup, воспроизводимые артефакты.
- Небольшая версионируемая спецификация состояния и conformance tests для
  сторонних адаптеров; документы остаются читаемыми человеком.
- Замер задержек hook на больших репозиториях: сейчас каждый snapshot хэширует
  все Git-видимые файлы. Оптимизировать после измерения, сохранив корректность.

Внешний ориентир — [OpenSSF Best Practices, passing](https://www.bestpractices.dev/en/criteria/0):
понятные интерфейсы, процесс участия, лицензия, версии, опубликованные тесты,
регрессионная политика и статический анализ. [OpenSSF Scorecard](https://scorecard.dev/)
дополняет проверку процесса разработки. Это полезные критерии, не сертификат
«отраслевого эталона» и не замена измерению качества передачи контекста.

## Изменения, выполненные самим аудитом

Созданы этот отчёт и новый журнал Codex. Под cooperative lock обновлены TASK
и черновик PLAN с предложениями. Исполняемый код, старые журналы и решения не
изменялись; commits/push не выполнялись. Дальнейшие исправления требуют отдельной
задачи владельца; предложение итераций не записано как одобренное решение.
